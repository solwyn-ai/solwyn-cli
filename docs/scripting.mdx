title: Scripting cost analytics
---

Use `--json` before `costs` for a versioned JSON envelope. Use `costs total` when
summing all spend: grouped results can contain only the top 100 groups. Inspect
`window.retention_clamped` and `truncated` before treating a result as complete.
A null savings upper bound is unknown, not zero savings.

```sh
solwyn --json --project "$SOLWYN_PROJECT_ID" costs total --range 7d
solwyn --project "$SOLWYN_PROJECT_ID" costs export --format json > costs.jsonl 2> costs-export.log
```

Export writes raw CSV or NDJSON rather than the CLI JSON envelope. Keep stdout and
stderr separate; stderr contains Core's `X-Solwyn-*` window headers and
`X-Solwyn-Export-Snapshot` when supplied. Raw exports are capped at 25,000 events
or 32 MiB; aggregate exports at 10,000 pricing subgroups. Oversized exports
and simulations (25,000 events) return 422, exit 2, and no partial result;
narrow the window.
Write exports to a temporary file and rename only after exit 0 so a failed
connection does not publish a partial file. Preserve CSV formula-safety prefixes.

MCP `get_costs` accepts the same filters and `from_`/`to` bounds. `get_cost_total`
returns uncapped totals and the effective window. Locally invalid cost queries
return `invalid_cost_query` with corrective guidance; malformed API responses
remain `invalid_costs_response`. Neither tool records spend or
mutates account settings. Use the tool's structured `ok` and `error` fields.

On a 503 with `Retry-After`, the shared client retries GET reads and metadata
ingest once, sharing the existing 429 retry budget and waiting at most
10 seconds (numeric seconds and HTTP dates are
supported). It never retries a download after yielding output bytes. Other
POSTs, including read-only cost simulation, are not automatically retried
on 503. Simulation receives a service-busy read hint. Capacity and rate-limit
retries share one replay allowance. A 401 is never replayed: there is no token
refresh.
Do not infer a write's outcome
from a generic service-busy response: inspect retained state before retrying.

MCP exposes the fixed `service_busy` error code with a local retry hint.
Single budget checks and durable journal admission receive a reservation-specific
hint on Core's fixed budget-busy detail: no reservation was made, so admission
is safe to retry. This does not promise zero side effects: advisory uncounted
tallies may already have been folded and can overcount on retry. The CLI's legacy
batch endpoint can return the identical busy detail after committing earlier
items; its failed chunk remains unknown even on the first chunk. Keep completed
results and do not blindly replay the failed chunk; later chunks were not submitted.

Ingest `not_recorded` requires a final status 503, `Retry-After: 1`, and exactly one of
Core's three rejection details: `Budget admission is busy; retry shortly`,
`Account tag registry is busy; retry the batch.`, or
`Accounting maintenance is in progress; retry the batch.` Every earlier attempt
must also be provably nonaccepting: a recognized rejection or Core's pre-ingest
429/401 response. A recognized final rejection cannot erase uncertainty from
an earlier potentially accepted attempt.
Missing/different headers, unrecognized HTML/JSON proxy responses, and transport
failures keep MCP
`recording=unknown` and CLI `status=failed` with retained call IDs. A valid 202
acknowledgement with complete canonical dispositions resolves the call normally.
Retry attribution with the same call identities and attempt indices regardless of
whether absence is proven. Durable journal `outcome_unavailable` retains its
existing code and unknown state; use the same operation ID with `recover_only`
to inspect it.
Other 503s, including accounting-gauge rebuilds, carry no absence guarantee.
CLI service-busy failures use existing exit 1, not an auth or budget-denied exit.

Credentials and tokens are never emitted. A 401 with `cli_credential_invalid`,
`cli_credential_expired` or `cli_credential_revoked` exits 3 with a
`Run solwyn login` hint. If a login request returns `account_membership_revoked`,
run `solwyn account recover` instead of repeatedly logging in. Recovery requires a
Solwyn login and idempotently creates a personal account when no active
membership exists (or returns the existing account); it emits
`solwyn.account.recover.v1` with `account_id`. Project keys cannot recover
accounts. Recovery is CLI-only.

User commands prefer the stored Solwyn login, then `SOLWYN_API_KEY`, then the
keychain project key. Set `SOLWYN_AUTH=project_key` to skip the login, or
`SOLWYN_AUTH=login` to require it; any other value exits 2. Metering commands
(`budget check`, `budget confirm`, `record`) use only a project key.

A change a login cannot make on its own (raising a cap, changing enforcement,
keys, billing, team or channels) returns an approval URL. The CLI prints it on
stderr, polls every 3 seconds for up to `--approval-wait` seconds (600 with a
terminal, else 90), then re-sends the exact same request once with the approval.
Exit 6 means the change was not applied: the approval is still pending, was
denied, expired, or no longer matches the request. The pending error names the
approval ID; approve it, then re-run the same command with `--approval ID`.
`solwyn login --wait 0` also exits 6 with `login_pending` and the code to relay.

Budget and quota periods use server receive time. Analytics use the event's
stored timestamp: a backdated batch counts against today's applicable budget
and quota period but appears on its original analytics day, subject to Core's
clock bounds and retention. Backdating cannot bypass current-period limits.

For subscription planning, use
`solwyn --json plan change --tier team --interval year --dry-run` or MCP
`plan_preview(tier="team", interval="year")`. Both are login reads at any role and
preserve integer cents, signed credits, currency, dates and proration lines.
Estimates are not price locks. Billing writes remain CLI-only and require the
owner's login, a browser approval, and interactive confirmation or `--yes`;
effects/prompts go to stderr and stdout holds one JSON result. Non-TTY use without `--yes` exits 2 before HTTP.
Checkout/portal links always print, never open a browser without a terminal, and
support `--no-browser`. Inspect known subscription/hosted state after write
503/transport failures; do not blindly replay. See the [plan reference](commands/plan.mdx).

Customer team/account reads need no selected project. MCP now exposes 33 reads in
both profiles and 37 tools in `guardrails`, with four existing writers unchanged.
`list_team_members` permits any account role; `list_team_invites` requires an
owner/admin login. Lists retain Core ordering and every invitation delivery status.
Team writes and account rename remain CLI-only. Use
`--yes` deliberately after reviewing their stderr effects; otherwise non-TTY writes
exit 2 before credentials or HTTP. Success JSON is one flat schema-bearing object
on stdout; error JSON is on stderr. See [team](commands/team.mdx),
[invite](commands/invite.mdx) and [account](commands/account.mdx).

`invite show` reads one private token from bounded stdin or a hidden prompt and
never sends Authorization. `invite accept` is retired: it exits 2 and asks you to
accept the invitation from the link in your email, then run `solwyn login`.
