Solwyn CLI 0.5.1 fixes what the WS-14 staging run-through of 0.5.0 found. The main fix is a security one: agent guidance and `keys env` no longer let a shell print the API key. It also stops hints from telling an agent to switch a repo's project, and fixes several small display problems.

Covers changes since [v0.5.0](https://github.com/solwyn-ai/solwyn-cli/releases/tag/v0.5.0).

## Install or upgrade

```sh
uv tool upgrade solwyn-cli                 # new installs: uv tool install 'solwyn-cli==0.5.1'
pipx upgrade solwyn-cli
pip install --upgrade solwyn-cli
solwyn --version                           # solwyn 0.5.1
```

Requires Python 3.11 or newer and the same Solwyn API as 0.5.0.

## Upgrading from 0.5.0

1. **`keys env` picks its format only from its own command line.** It prints export lines unless `--json` or `--format json` is on the command line. `SOLWYN_FORMAT=json` and config `format = "json"` no longer apply to it. Scripts that relied on `SOLWYN_FORMAT=json` for `keys env` JSON must pass `--json`. Never eval JSON output.
2. **Rerun `solwyn init --agents`** in repos set up with 0.5.0 to replace the agent guidance in `AGENTS.md`, `.claude/skills/solwyn/SKILL.md` and `.cursor/rules/solwyn.mdc` (see Security).
3. **`init`'s `key_stored`** (JSON) and "Key stored" (table) now say whether a key for the project is stored on this computer, whether this run stored it or an earlier one did. In 0.5.0 they meant "stored by this run", so a repo whose key was already stored read "no".
4. **`project_mismatch`** keeps its code and exit code (2). Its message now names the two values and stops there. The advice moved to the hint, which is addressed to a person (see Changed).

## Security

- **Agent guidance no longer hands the key over with a bare `eval`.** The guidance `init --agents` writes, `agent-context`, and the `keys env` help said to run `eval "$(solwyn keys env)"`. That form exports the key into the agent's long-lived shell. With `SOLWYN_FORMAT=json` or config `format = "json"`, `keys env` printed JSON instead of export lines. zsh's eval then failed with "no matches found" and repeated the whole payload, key included, into the agent's transcript. bash shows only the first word. Every surface now gives one form, run in a subshell with an explicit table format:

  ```sh
  (solwyn_env="$(solwyn --format table keys env)" && eval "$solwyn_env" && exec <command>)
  ```

  The key reaches only `<command>`. Nothing runs when `keys env` fails, and the parent shell never holds the key.
- **`keys env` is safe whatever the instructions say.** It prints export lines unless JSON is asked for on its own command line, so no format setting can turn its output into a word a failing shell repeats. Tests run the CLI under bash and zsh with `SOLWYN_FORMAT=json` and config `format = "json"`, with failing `keys env` runs, and with the subshell form. They assert that the key never appears on the shell's stdout or stderr.

## Changed

- **The `project_mismatch` hint asks a person.** The CLI used to say "Edit .solwyn.env if the repo should use another project". On a computer that holds keys for both projects, an agent could follow that and switch the repo to the other project's budget. The CLI now says: "The repo's .solwyn.env names checkout-bot. Ask a person to change it if this repo should use another project. Never switch projects to get past a budget limit." Read commands that warn instead of failing say the same. The MCP hint says: "Ask a person to change .solwyn.env if this repo should use another project, or to restart the server with the project it names. Never switch projects to get past a budget limit." The agent guidance still says never to change `.solwyn.env`, `SOLWYN_PROJECT` or `--project` to get past a limit.
- **Sub-cent amounts.** Tables show dollar amounts with at least two decimals, and up to six when an amount has sub-cent digits. A $0.002 cap reads `0.002`, not `0.00`. Float noise past the sixth decimal is dropped from tables. JSON and MCP output carry Core's values unchanged.
- **Approval expiry.** The "expires in N minutes" line never exceeds the approval's own window on the server (`expires_at - created_at`). A local clock behind the server's made a 10-minute approval read "11 minutes".
- **`whoami` with a login names the project.** `configured_project` is the selected project (`--project`, `SOLWYN_PROJECT` or `.solwyn.env`) for a login as well as for an API key. Over MCP, `get_whoami` shows the launch project instead of `null`.
- **Table width.** Tables use `COLUMNS` when it is set, then the terminal's width on a TTY, then 80 columns. `COLUMNS=200 solwyn keys list | less` no longer wraps each key over four lines.
- **`login --continue`** checks the stored login first. When it is already approved, the CLI does not show the page and code again. While the login is still pending, they are shown once.

## Not changed

- JSON and MCP amounts such as `0.0014810000000000001` are Core's floats, passed through unchanged. Rounding them in the CLI would change the data.
