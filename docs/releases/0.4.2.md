Solwyn CLI 0.4.2 fixes two problems found while testing 0.4.0 on a Mac against a staging API. A 0.3 Keychain item that logout cannot delete no longer makes every `solwyn logout` fail. `solwyn config set` now writes only the key you set, never defaults.

Covers changes since [v0.4.1](https://github.com/solwyn-ai/solwyn-cli/releases/tag/v0.4.1).

## Install or upgrade

```sh
uv tool upgrade solwyn-cli                 # new installs: uv tool install 'solwyn-cli==0.4.2'
pipx upgrade solwyn-cli
pip install --upgrade solwyn-cli
solwyn --version                           # solwyn 0.4.2
```

No new login is needed after upgrading from 0.4.0 or 0.4.1. Requires Python 3.11 or newer.

## Fixed

- **A 0.3 credential logout cannot delete no longer fails logout.** On macOS, a Keychain item saved by CLI 0.3 (service `solwyn-cli`, account `api_key`) can belong to the older Python that created it. Deleting it then needs a confirmation that macOS cannot show over SSH, to an agent or in CI, so the delete fails or does nothing. 0.4.0 and 0.4.1 reported the whole Keychain as `unreachable` and exited `3` on every logout, even though the server revoke and this API's login were cleared. Now a 0.3 entry that cannot be deleted is reported as kept, and logout exits `0` when this API's login and entries were cleared. Logout says how to remove the item: delete the `solwyn-cli` item in Keychain Access (macOS) or Credential Manager (Windows), or run `solwyn logout` again from a desktop session, where the system can ask. A failure to delete this API's own entries still exits `3` with `logout_incomplete`.
- **`config set` writes only the key you set.** It used to write every setting with its default into `config.toml`, so `solwyn config set credential_store auto` saved `api_url = "https://api.solwyn.ai"` although you never set it. Now `config set`, `solwyn login --store`, `solwyn init` and clearing a deleted default project write only their own keys and keep the ones already saved. A file written by 0.4.0 or 0.4.1 keeps its saved values; `config list` and `doctor` still report a saved production `api_url` as the default.

## Compatibility

- `solwyn.logout.v1` gains `legacy_kept` on each store: the 0.3 entries logout could not delete. A store's `status` and `cleared` now cover this API's entries only.
