Solwyn CLI 0.5.2 fixes six bugs a state-machine audit found where a server-side change and local state could drift apart. A new API key could be left live with nobody holding it. A failed `init` could leave a project behind that a rerun duplicated. A leftover environment variable could redirect alerts. An approved budget change could erase rules added while it waited. One network error could switch off MCP reporting until restart. And `.solwyn.env` could go missing during a rename.

Covers changes since [v0.5.1](https://github.com/solwyn-ai/solwyn-cli/releases/tag/v0.5.1).

## Install or upgrade

```sh
uv tool upgrade solwyn-cli                 # new installs: uv tool install 'solwyn-cli==0.5.2'
pipx upgrade solwyn-cli
pip install --upgrade solwyn-cli
solwyn --version                           # solwyn 0.5.2
```

Requires Python 3.11 or newer and the same Solwyn API as 0.5.1.

## Upgrading from 0.5.1

Exit codes 0–6 are unchanged, and JSON output only gains fields.

1. **`channels update` reads `SOLWYN_CHANNEL_SECRET` only with `--secret-env`.** Scripts that set the variable to replace a channel's webhook URL or token must add `--secret-env`. Without the flag the variable is ignored with a note on stderr. When it is the only input, `update` exits 2 (`invalid_notification_request`). `channels create` is unchanged.
2. **`init --run-cap` failures have their own code.** When the project is created but its run cap cannot be added, `init` exits 1 with `run_cap_failed` instead of `invalid_projects_response`.
3. **`budget set` can return `budget_configuration_changed`** (exit 1) when the budget changes between its two reads. Nothing was written; rerun it.
4. **An approved budget change can return `budget_changed_during_approval`** (exit 6) when the budget changed while the approval waited. Nothing was sent; rerun the command.

## Fixed

- **A new key is always stored, shown once, or revoked.** If storing the key failed, or Ctrl+C landed after Core created it, `init`, `projects create --store-key` and `keys create --store-key` could leave the key live and unknown to anyone. Now:
  - On a terminal, the key is shown once (like `keys rotate`), the command exits 0, and JSON has `stored: false` (`key_stored: false` for `init`) plus a `key` field.
  - Anywhere else (a pipe, a log, an agent) the key is revoked and the command exits 3 with `credential_storage_failed`. The message and hint name the key and what to run next.
  - An error exit or interrupt before the key is stored or shown revokes it and says so on stderr. If the revoke fails, the note gives the `solwyn keys revoke` command to run.
  - `login` revokes a login it cannot store on Ctrl+C as well as on errors.
- **`init` records the project before anything else can fail.** It writes `.solwyn.env` right after the project is created, before the key store and the run cap. Any later failure or interrupt prints `Project proj_… was created. Finish setting it up with: solwyn --project proj_… init` just before the JSON error, so a rerun finishes the same project instead of creating `<repo>-2`.
- **`channels update` no longer picks up a leftover secret.** A `SOLWYN_CHANNEL_SECRET` left in the environment silently replaced the channel's webhook URL or token and exited 0 (see Upgrading).
- **Approved budget changes no longer erase newer rules.** A budget change that needed browser approval resent a full configuration built before the wait, up to 10 minutes earlier, which removed rules added in the meantime. The CLI now re-reads the budget after approval and sends only if nothing changed. `budget set` also reads twice before writing, like `budget rule add`.
- **MCP reporting survives a network error at startup.** A connection error, 429 or 503 on the account lookup was remembered as a refusal for the server's lifetime. These are now retried on the next call. Every refusal the server does keep until restart now says "Restart the MCP server" in its hint.
- **`.solwyn.env` is put back if a rewrite fails.** An interrupt, or a file system that refuses hard links, during `projects rename` could leave `.solwyn.env` missing with its contents in a hidden file. The CLI now restores it, never over a file another process wrote meanwhile. If a copy is left behind, the error names it, and `projects rename` prints where it is.
