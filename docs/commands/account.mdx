# Account and identity reads

```sh
solwyn whoami
solwyn --json whoami
solwyn account phone show
solwyn --json account phone show
```

JWT `whoami` shows email verification along with user/account identity, role,
seats and projects (`solwyn.whoami.v1`). Its strict identity parser adopts
`email_verified`, first name and marketing email subscription state. Project keys
return local authentication and selected-project context without inventing a user
or verified email, and never reveal raw key material. MCP provides `get_whoami`.

`account phone show` (`solwyn.account.phone.v1`) requires JWT and reads the current
user's state: none, pending, verified or verified_with_pending_change; verified
and pending numbers, verification/resend timestamps, and SMS consent/disclosure
state. Verified phone and SMS consent are prerequisites for SMS notifications.
Absent timestamps remain null. Verification and consent changes stay in the
dashboard. MCP provides `get_account_phone` in both profiles. Account recovery
remains CLI-only.

## Rename the current account

```sh
solwyn account rename "New account name"
solwyn --json account rename "New account name" --yes
```

Rename requires owner JWT. It reads the current account and displays its ID,
old/new names and invitation-email effects before confirmation or `--yes`.
Non-TTY use without `--yes` exits 2 before reading credentials or HTTP.
The PATCH sends only `display_name`; `alert_email_override` remains untouched.
Use the existing `account alert-email show|set|clear` commands to manage that
independent preference.

Core normalizes display names, rejects controls/bidi/zero-width characters and
limits them to 120 characters. Invalid input uses fixed errors without reflecting
validation values. `solwyn.account.rename.v1` returns the complete strict account
response: ID, display name, tier, alert-email override, seat limit/usage and your
role. Rename remains CLI-only. Inspect account state before deliberately retrying
an uncertain write; see [team management](team.mdx).
