---
title: Login and logout
---

Login prompts for user credentials or accepts a project key with `--with-key`.
Passwords and keys never belong in command-line arguments or echoed output.
Keys are read through a hidden prompt or explicit stdin; stored credentials go
only to the OS keychain. Key login validates the local key shape and stores it;
it does not make a remote authentication probe.

```sh
solwyn login
solwyn login --with-key
solwyn logout
```

Environment keys, stored project keys, then stored JWT are the credential
precedence. Even an empty/invalid environment key prevents fallback. JWT-only
commands require unselecting any masking key. Logout clears local keychain
credentials; it does not revoke remote project keys.

Global `--project`, `--api-url` and output flags precede the command.
Use `--json` for the schema named below unless the command emits plain text.

## `solwyn login`

Authenticate with Solwyn.

```console
Usage: solwyn login [OPTIONS]
```

| Argument or option | Meaning | Default |
| --- | --- | --- |
| `--with-key` | `Read and store a project API key from a hidden prompt or stdin. (BOOL)` | `False` |

```text
Endpoint: POST /api/v1/auth/login or local keychain write with --with-key
Auth: none
Exit codes: 0 success; 1 generic/API; 2 usage; 3 auth or credential storage
JSON schema: solwyn.login.v1
Keys and passwords are never accepted as command-line arguments or echoed.
Read project keys only from a hidden prompt or stdin; passwords use a hidden prompt.
```

## `solwyn logout`

Clear all stored Solwyn credentials.

```console
Usage: solwyn logout [OPTIONS]
```

```text
Endpoint: local keychain clear
Auth: local (none)
Exit codes: 0 success; 2 usage; 3 credential storage
JSON schema: solwyn.logout.v1
```
