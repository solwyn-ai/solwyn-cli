`whoami` names the credential in use first: `Credential: CLI login dev-laptop
(read, contain), expires 2026-11-29` for a Solwyn login, or `Credential: project
key (environment)` for a key. A login also reads user and account identity,
role, seats and projects, and keeps email verification state. An API key
returns only the local credential source and selected-project context, with no
network lookup, user identity or raw key material. The login comes before any
API key, so a stored key no longer hides it; see [login](login.mdx) for the
order and `SOLWYN_AUTH`.

```sh
solwyn whoami
solwyn --json whoami
```

The output uses `solwyn.whoami.v1` (`auth_type` is `login` or `project_key`, and
`credential` carries the kind, source, label, scopes and expiry); MCP exposes
`get_whoami`. See [account](account.mdx) for phone prerequisites and
personal-account recovery in the dashboard.

Global `--project`, `--api-url` and output flags precede the command.
Use `--json` for the schema named below unless the command emits plain text.

## `solwyn whoami`

Show the current Solwyn identity and project context.

```console
Usage: solwyn whoami [OPTIONS]
```

```text
Endpoint: local key identity or GET /api/v1/account/me, GET /api/v1/accounts/me, and GET /api/v1/projects
Auth: any
Exit codes: 0 success; 1 generic/API; 2 usage; 3 auth
JSON schema: solwyn.whoami.v1
```
