---
title: Repository setup
---

Run from the repository to configure its Solwyn project, detect Python provider
SDK imports, print SDK wiring and read budget status. Provider credentials are
never collected. `--agents` additionally writes Claude, Cursor and AGENTS.md
guidance; `--run-cap` applies only to newly created projects.

```sh
solwyn init
solwyn init --agents
```

With no stored credential, init runs the same browser login as `solwyn login`.
In a terminal it first asks whether to log in or store a project key; without a
terminal it starts the browser login, so agents and SSH sessions are not stuck.
If the approval wait ends first, it exits 6 with `login_pending`; approve in the
browser, run `solwyn login --continue`, then run `solwyn init` again. Signup and
email verification happen on that browser page.

Init then lists and selects projects and can create one. Creating a project with
a Solwyn login needs one browser approval (see [approvals](approvals.mdx)), and
shows a one-time project key that init stores in the keychain. It writes local
configuration and scans imports, then verifies the budget with a read. Keychain
access requires the same OS account. The help contract below lists every
conditional remote and local operation.

Global `--project`, `--api-url` and output flags precede the command.
Use `--json` for the schema named below unless the command emits plain text.

## `solwyn init`

Configure Solwyn safely for the current repository.

```console
Usage: solwyn init [OPTIONS]
```

| Argument or option | Meaning | Default |
| --- | --- | --- |
| `--agents` | `Write Claude, Cursor, and AGENTS.md guidance. (BOOL)` | `False` |
| `--run-cap` | `Create a wildcard per-run hard cap after project creation; caps every run at min(caps).  (FLOAT)` | `None` |

```text
Endpoint: composite onboarding workflow
Auth: any, or a browser login when none is stored
Exit codes: 0 success; 1 generic/API; 2 usage; 3 auth; 5 not found; 6 approval or login pending
JSON schema: solwyn.init.v1
Remote operations: conditional browser login (POST /oauth/device_authorization, POST /oauth/token); GET /api/v1/projects; optional POST /api/v1/projects; final GET /api/v1/projects/{project}/budget; --run-cap adds a rule with GET/GET/PUT /api/v1/projects/{project}/budget after creation.
Local operations: write local configuration; scan Python imports; render SDK snippets; optionally write agent artifacts with --agents.
Provider credentials are never collected; --agents writes safe agent guidance.
```
