---
title: Project notifications
---

Read or update selected-project routing. Reads accept a project key or JWT;
settings writes need a full-scope key or JWT. Omitted options keep current
settings. `--clear-channels` clears channel references and `--all-events` clears the
event filter to allow all events;
email/SMS resets send explicit null. Core accepts future event names.

```sh
solwyn --project proj_example notifications show
```

Channel availability follows Core's returned capabilities. SMS needs Production,
a verified phone and consent; verification/consent flows stay in the dashboard.
Slack/PagerDuty/email tests send real deliveries; SMS tests check eligibility
without sending a message. Slack/PagerDuty credentials are read
through stdin or environment input, not secret arguments.

Global `--project`, `--api-url` and output flags precede the command.
Use `--json` for the schema named below unless the command emits plain text.

## `solwyn notifications`

Manage project notification routing.

```console
Usage: solwyn notifications [OPTIONS] COMMAND [ARGS]...
```

```text
Endpoint: composite router for notifications subcommands
Auth: varies by subcommand
Exit codes: 0 success; 2 usage
JSON schema: varies by subcommand
```

## `solwyn notifications set`

Change only the notification settings explicitly selected.

```console
Usage: solwyn notifications set [OPTIONS]
```

| Argument or option | Meaning | Default |
| --- | --- | --- |
| `--channel` | `Channel ID; repeat to replace the reference list. (STRING; repeatable)` | `None` |
| `--clear-channels` | `Remove every channel reference. (BOOL)` | `False` |
| `--severity` | ` (Choice(['info', 'low', 'warning', 'medium', 'high', 'critical']))` | `None` |
| `--event` | `Event type; repeat. Core accepts future event names. (STRING; repeatable)` | `None` |
| `--all-events` | `Allow all event types. (BOOL)` | `False` |
| `--email/--no-email` | ` (BOOL)` | `None` |
| `--sms/--no-sms` | ` (BOOL)` | `None` |
| `--reset-email` | `Reset email to its enabled default. (BOOL)` | `False` |
| `--reset-sms` | `Reset SMS to its disabled default. (BOOL)` | `False` |

```text
Endpoint: PUT /api/v1/projects/{project}/notifications
Auth: any; full-scope key for writes
Exit codes: 0 success; 1 generic/API or delivery failure; 2 usage; 3 auth; 5 not found
JSON schema: solwyn.notifications.v1
Omitted options leave settings unchanged. Clear channel/event lists with []; reset email/SMS configs with null.
Channel enablement follows Core capabilities; SMS requires Production, verified phone and consent.
```

## `solwyn notifications test`

Test delivery or SMS eligibility; failure exits 1, including HTTP 200 failures.

```console
Usage: solwyn notifications test [OPTIONS] CHANNEL:{slack|pagerduty|sms|email}
```

| Argument or option | Meaning | Default |
| --- | --- | --- |
| `channel` | ` (Choice(['slack', 'pagerduty', 'sms', 'email']); required)` | `None` |
| `--secret-stdin` | `Read Slack webhook URL or PagerDuty routing key from stdin. (BOOL)` | `False` |

```text
Endpoint: POST /api/v1/projects/{project}/notifications/test-{channel}
Auth: any; Slack/PagerDuty require JWT or full-scope key; email requires JWT
Exit codes: 0 success; 1 generic/API or delivery failure; 2 usage; 3 auth; 5 not found
JSON schema: solwyn.notifications.test.v1
SMS checks eligibility only (no message sent). Slack, PagerDuty and email send a real test. Slack/PagerDuty require --secret-stdin or SOLWYN_CHANNEL_SECRET; use channels test ID for stored credentials.
Core enforces per-channel capabilities; SMS is Production+ and requires phone verification and consent.
```
